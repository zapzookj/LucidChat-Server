### ★ 시작 전 반드시 볼 정정 3건

**정정 1 — `dominantStat()` 동점 문제는 300/100으로 해결되지 않는다.**

결정 기록([`decisions_confirmed.md`](19_assets/decisions_confirmed.md) §G-6 ★)의 원문:

> **300/100이면 3축까지만 만렙이라 고르지 않을 수 없다. 지배 스탯이 다시 의미를 갖는다.**
> 즉 이 정정은 밸런스 조정이면서 **동시에 결함 수정**이다.

**코드는 그렇지 않다.** `TheaterState.java:471-479` 실측:

```java
public AvatarStat dominantStat() {
    AvatarStat best = AvatarStat.CHARM;
    int bestValue = statCharm;
    if (statWit > bestValue) { best = AvatarStat.WIT; bestValue = statWit; }
    if (statBoldness > bestValue) { best = AvatarStat.BOLDNESS; bestValue = statBoldness; }
    if (statIntellect > bestValue) { best = AvatarStat.INTELLECT; bestValue = statIntellect; }
    if (statEmpathy > bestValue) { best = AvatarStat.EMPATHY; }
    return best;
}
```

비교가 전부 엄격 `>`이고 초기값이 CHARM이다. **300/100에서도 3축 100 배분(100/100/100/0/0)이면 동점 → CHARM 고정이다.** 축 개수만 5→3으로 줄었을 뿐 퇴화 케이스는 그대로다.

→ **G-6은 밸런스 조정으로서 유효하나, "부수 효과가 결함 수정"은 성립하지 않는다.** 동점 타이브레이크는 **별건 결함**으로 세워야 한다(배치 8).
→ 그리고 `docs/25` §2의 검증 절차 *"3축 만렙 시 지배 스탯이 그 축으로 잡히는지"*는 **아무것도 판별하지 못한다** — 그대로 돌리면 실패하고, 다음 사람이 G-6 구현이 잘못됐다고 오판한다.

**정정 2 — `F-1.a` 수정 지점의 BE 좌표가 틀렸다.**

`docs/25`와 원장이 낡은 주석으로 지목한 `TheaterLobbyService.java:652-653`은 **지금 맞는 주석**이다:

### ★ §2-7의 역방향 함정 — V36을 **명시적으로 써야 하는** 이유

`peak_status_level`은 `@Enumerated(EnumType.STRING)` 신규 컬럼이다. **V36 없이 배포하면** 프로드의 `ddl-auto=update`(§1-3 실측)가 컬럼을 만들면서 **값 목록 CHECK를 자동 생성한다**(Hibernate 6.6). 그러면 훗날 `RelationStatus`에 값을 하나 추가하는 순간 **V31과 똑같은 사고**(부팅 성공·런타임 500)가 재현된다.

Flyway가 먼저 돌아 컬럼이 이미 있으면 Hibernate update는 건드리지 않으므로 CHECK가 붙지 않는다.

→ **V36에 CHECK를 붙이지 말 것.** 그 이유를 마이그레이션 파일 주석에 남긴다.

**스코프 전체에 enum 값 추가는 0건**임을 별도로 확인했다(DB 영속 enum 45개 전수 대조). `F-2`의 `outcome`은 `TheaterResponses.java:301 String outcome, // FAIL / SUCCESS / GREAT_SUCCESS`로 **String이지 enum이 아니다.**
