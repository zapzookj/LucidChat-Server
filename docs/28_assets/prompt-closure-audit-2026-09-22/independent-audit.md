# 모델·프롬프트 실험 종료 독립 감사 — 2026-09-22

별도 컨텍스트 `experiment_audit`가 현재 파일을 읽어 재검토했다. 추가 에이전트·유료 API·소스 수정·원장 수정·브랜치 전환은 하지 않았다. 이 보고서만 새로 작성했다. 기존 9/18 보고서의 결론을 현재 checkout의 구현 사실로 자동 승계하지 않았다.

## 판정

**모델 탐색과 이번 프롬프트 실험은 종료해도 된다. 초기 계획 전체 완료나 현재 운영 코드 수리·검증 완료로 종료해서는 안 된다.**

376회는 충분히 많은 호출이지만 독립적인 376개 상황이나 서비스 전반의 검증은 아니다. 로제타 일반 모드·고정 관계/상태에 집중한 탐색에서 복잡한 창작 지시와 현재 턴 재주입의 일관된 이득을 입증하지 못했다. 이미 사용자에게 확정된 Gemini 3 Flash 유지와 마지막 실험 종료 결정을 뒤집어 예산 잔액을 소진할 이유는 없다.

이번 종료를 위해 더 필요한 것은 무제한 후보 탐색이 아니라 **현재 상태의 정정, 수리 제안의 복구 가능성 보존, 운영 적용 전 미완료 항목의 명시적 인계**다. 이를 보고서에 반영하면 실험을 닫을 수 있다. 실제 적용 완료를 선언하려면 별도로 현재 코드와 통합하고 검증해야 한다.

## 1. 현재 checkout과 9/18 기록의 차이

직접 관측한 현재 checkout은 `feature/diorama`, HEAD `4e58311731c88f6e869b6c295b8970123a5ceae5`다. 9/18 기록의 `codex/llm-bakeoff-lab` / `ca27320`과 다르다.

- 현재 `CharacterPromptAssembler.java:260`에는 user 메시지를 항상 발화로 읽으라는 이전 지침이 남는다.
- 현재 `StoryDirectorPromptAssemblerV2.java:158`, `:373`, `:514`에는 사용자 내면/미제시 외적 반응 지시가 남고, `:324`에는 Extended Backstory 중복 구획이 남는다.
- 현재 `build.gradle`에는 bakeoff sourceSet/prepareBakeoff 등록이 없으며 `LegacyFeatureProperties`, `SceneIllustrationProperties`, `WorldViewService` 소스도 없다. root가 보고한 선정 계약 테스트의 `compileTestJava` 13오류와 부합한다. 감사자는 해당 실패 명령을 다시 실행하지 않았으며, 의존 소스 부재와 빌드 등록 부재를 독립 확인했다.
- 따라서 9/18 Java 계약23·Node93·bootJar·144개 재조립 성공은 **그 당시 소스의 검증 기록**이다. 현재 branch의 빌드·작동 보증으로 사용할 수 없다. 이번 감사에서 현재 Java bridge를 실행해 그 결과를 재현했다고 주장하지 않는다.

수리 제안 소스는 build 아래 별도로 존재하며 읽은 파일의 SHA-256은 다음과 같다.

| 제안 | 경로 | SHA-256 |
|---|---|---|
| V1 | `build/bakeoff/proposed-production/free/CharacterPromptAssembler.java` | `71d380d613affcceaad210b36d72d47e8e0b642342f30343b8c50f32e0be844f` |
| V2 | `build/bakeoff/proposed-production/story/StoryDirectorPromptAssemblerV2.java` | `3e7f49516473734ad1c7c1d2fc295876c0b39daec83576988448b847d7f38d1e` |

build 경로는 통상 정리 가능한 산출물 경로다. 종료 인계에는 기준 commit과 hash가 있는 복구 patch 또는 동등한 보존본이 필요하다. 최종 읽기 검토에서 [복구 patch](repairs-against-ca27320.patch)와 [recovery-manifest.json](recovery-manifest.json)의 생성을 확인했으며, patch 파일의 SHA-256은 manifest와 일치한다. root는 ca27320을 추출한 무시된 임시 경로에서 git apply 검사·적용을 수행하고 LF 정규화 후 위 두 제안본 hash와 일치함을 기록했다. 감사자가 이 적용 작업을 재실행한 것은 아니며 현재 src/main에도 적용하지 않았다. 이 패치는 assembler 두 곳의 복구 자료이고, 다른 기반 branch나 전체 빌드 환경을 그대로 복원한다고 단정해서는 안 된다.

개인정보·과금 자료 제외도 현재 Git 조건으로 확인했다. `.git/info/exclude`의 정확한 `/tools/llm-bakeoff/.env.local`, `/tools/llm-bakeoff/.local/` 규칙이 각각 키 파일·원장 파일에 적용되며 README에는 적용되지 않는다. 키 파일 내용은 읽지 않았다. 이 보호는 해당 checkout의 로컬 설정이므로 저장소를 다른 곳에 전달할 때 자동 승계되는 규칙은 아니다.

## 2. 376회·비용·증거 재대조

2026-09-22에 원본 JSON을 읽어 다시 합산하고 대응 관계를 검사했다.

| 세션 | 결과/원장 항목 | 실비 USD | strict JSON 실패 | 기존 Java 판정 non-ok |
|---|---:|---:|---:|---:|

| Round2 | 128 | 0.5033124833 | 11 | 0 |
| Round3 | 28 | 0.1180507833 | 0 | 0 |

| 합계 | **376** | **1.4735847333** | **31** | **2** |

합산 순서에 따른 이진 부동소수점 최하위 차이 외에 기존 보고 금액과 불일치가 없다. 원래 $3 대비 잔액은 약 $1.5264152667이다. 모든 세션과 전역의 미확정 예약은 0이다. 과거 모델 비교42회까지 포함한 전역은 418항목, $1.6429894366666682다. 모델 비교 비용을 프롬프트376회의 비용에 혼입하지 않았다.

직접 확인한 항목:

- 12개 phase의 계획 jobs와 실제 결과 집합이 일치한다. 누락·추가·변조 job이 없으며 session/phase/job으로 식별한 376개 호출과 generation ID는 각각 고유하다. 같은 개발 사례의 후속 반복은 다른 phase의 반복 실험이며 독립적인 새 상황으로 세면 안 된다.
- 모든 결과의 전역/세션 예약 ID·runId·상태·최종 실비·usage.cost가 대응한다. 실비는 예약액을 넘지 않으며 입력/출력 비용 분해합도 일치한다.
- 모든 prepared.messages와 실제 request.messages 및 promptHash가 일치한다. 요청/실제 모델은 Gemini 3 Flash, provider는 Google AI Studio/default이며 temperature0.8·기본 reasoning·출력 한도·fallback 금지 조건이 기록과 일치한다.
- 기존319파일을 `final-preserved-originals.json`의 SHA-256과 다시 대조해 전부 동일했다. 최종 유료 호출 전 3개 계획 파일의 SHA-256도 동일하다. 최종 manifest가 보존한 이전346개 전역 원장 항목도 동일하다.
- 마지막72개의 공개 responses.json 장면·입력·상태·실비·strict 판정은 원본 결과에서 다시 읽은 값과 전부 일치한다.

strict JSON31건과 기존 Java non-ok2건은 같은 개념이 아니다. 일부는 첫 유효 객체 뒤의 여분 토큰을 기존 Java parser가 허용한 경우다. 마지막2건도 P0의 후행 `] }`이며 서비스 파싱 실패2건으로 바꾸어 표현하면 안 된다. 실패 응답도 위 호출·비용에 포함했다.

이 감사는 로컬 기록과 provider가 돌려준 usage를 대조한 것이다. 별도의 provider 청구 명세나 외부 계정 상태는 조회하지 않았다.

## 4. 종료에 필요한 것과 선택 후속

**이번 탐색을 종료할 때 필수인 정리:**

1. docs/28와 인계의 9/18 완료 문구가 역사적 기록임을 표시하고, 9/22 현재 branch·수리 미적용·현재 계약 테스트 실행 전 실패를 명시한다.
2. build에만 남아 있는 수리 제안·기준 commit·hash·관련 테스트의 복구 자료를 보존한다. 현재 branch에 적용했다고 표현하지 않는다.
3. ‘Gemini 유지·복잡한 후보 미채택·실험 종료’와 ‘현재 코드 통합/P1 최종 검증 미완료’를 별도 상태로 남긴다. 남은 예산은 추가 호출 의무가 아니다.

**운영 반영 또는 프롬프트 개선 완료 선언 전에 필요한 후속:**

- 적용할 Git 기반을 정한 뒤 그 기반의 API·의존성에 맞춰 수리를 통합하고 계약/컴파일/실제 조립 경로를 다시 검증한다. 과거 patch를 무조건 현재 branch에 덮어쓰는 방식은 적절하지 않다.
- 최종 실제 전송 P1을 고정한 뒤 P0 대비 대표 실패 입력과 정상 입력으로 최소한의 생성 회귀를 확인한다. 이때 사용자/제작자 한국어 검토를 포함하고, J2 성적을 대리 근거로 쓰지 않는다. 현재 요청에서 새 유료 실행을 하라는 뜻은 아니다.
- 배포 범위가 다른 인물·시크릿·이벤트까지라면 해당 범위의 계약과 대표 생성 퇴행을 확인한다. 로제타 결과만으로 일반화하지 않는다.

**별도 목표가 생기면 선택할 후속:**

- 장기 일관성이 목표라면 prompt 문구 추가보다 먼저 실제 요약 주기·처리 구간·delta 누락/중복·요약 출처를 재현하고 고친다.
- 유지보수성과 상태 출처 문제가 커지면 loader/composer 분리를 추진하되, 그 자체를 대사 품질 개선으로 보고하지 않는다.
- 더 빠른 첫 씬이나 비용 절감이 필요하면 V1 reasoning/event_status 순서·실제 FE 표시·캐시 조건·sampling을 한 축씩 측정한다.
- 새 모델 비교는 가격·지연·품질 요구나 모델 변화라는 새 이유가 생길 때 다시 연다. 이번 자료만으로 모델 탐색을 계속할 필수 이유는 확인하지 못했다.
