### 보존과 보호 조치

`build/bakeoff/proposed-production`에 남은 두 수리본을 확인하고, **ca27320 기준의 [복구 패치](prompt-closure-audit-2026-09-22/repairs-against-ca27320.patch)**와 [해시·검증 명세](prompt-closure-audit-2026-09-22/recovery-manifest.json)를 만들었다. 패치는 무시된 임시 경로에서만 적용 검사했다. 복원 결과를 LF로 정규화하면 당시 두 제안본의 SHA-256과 일치한다. 현재 `src/main`에는 적용하지 않았다. 이 패치는 assembler 두 곳만 포함하며 Gradle·Git 제외 규칙·전체 실험 환경의 복구까지 포함하지 않는다.

현재 공유 `.gitignore`에는 실험용 키/원장 제외 규칙도 빠져 있었다. 실제 `.env.local`과 `.local/budget.json`이 미추적 대상으로 나타나는 것을 확인했고, 키 내용을 읽지 않은 채 `.git/info/exclude`에 정확한 두 경로만 추가했다. 실제 키/원장은 제외되고 README는 제외되지 않는 것을 검증했다. 확인한 두 파일은 Git 추적 중이 아니었다. 외부 노출이나 과거 이력의 안전성까지 조사한 것은 아니다. 이 로컬 제외 규칙은 다른 clone에 전파되지 않으므로 통합 시 공유 `.gitignore`도 복원해야 한다.

원래 있던 `application.yml` 변경과 다른 미추적 작업은 보존했다. 브랜치 전환·stash 적용·제품 소스 덮어쓰기·커밋·푸시·배포는 하지 않았다. 복구 자료와 문서도 아직 미커밋 상태다.

## 4. 최종 P1을 확인해야 하는 이유

실험 J2는 로제타 중심의 예시를 사용했다. 9/18에 서비스 적용용으로 정리한 P1은 여러 인물에 사용할 중립 예시로 바꾸었고, V2에는 환경 장면3개·`speaker:null`·빈 dialogue·빈 stat_changes가 들어간다. 예시를 그대로 복제하지 않도록 설명했지만, 모델이 이 형식을 과도하게 따라 대사나 스탯 변화를 줄이는지는 생성하지 않고는 알 수 없다. 이는 **발견된 출력 퇴행이 아니라 확인해야 할 전이 위험**이다.

또한 당시 로제타 고정 fixture의 system 길이는 V1 **27,367→29,664(+8.4%)**, V2 **15,475→18,021(+16.5%)**였다. UTF-16 코드 단위이지 토큰 수가 아니다. 중복 제거가 있어도 유효 예시/필드 설명 추가로 전체는 늘었다. 최종 P1의 비용·첫 씬 지연이 개선됐다고 보고할 근거는 없다.

전체 실험을 다시 여는 대신, 적용할 P1 전송본을 고정한 뒤 다음 수용 검사를 완료하는 것이 적절하다.

1. 올바른 통합 기반에서 두 assembler 수리와 빌드/테스트/공유 제외 규칙을 연결한다. 의도한 diff를 확정하고 실제 조립·컴파일·계약 검사 및 배포물 격리를 다시 검증한다.
2. 정상 입력과 과거 실패 입력으로 발화/행동/미실행 계획, 외형, 사용자 선택권, JSON/화자/모드별 필드를 확인한다. 자유·스토리, 오프닝/이벤트, 다인물, 다른 개성의 인물 등 실제 수정 범위를 대표하는 작은 사례 집합을 사용한다. 시크릿 경로의 프롬프트/계약도 비노골적 입력으로 점검할 수 있다.
3. 실제 history→생성→SSE 표시 경로에서 첫 씬·대사 유무·씬 구성·스탯 변화의 퇴행과 usage를 확인한다. 최종 예시의 과도한 복제 여부도 포함한다.
4. 최종 P1의 한국어/캐릭터 표현을 소량이라도 사용자 또는 제작자 관점에서 검토한다. J2 성적이나 AI judge 점수로 이 확인을 대체하지 않는다.

이 통합과 수용 확인이 끝나면 이번 과제의 구현 범위도 닫을 수 있다. 모든 장기 최적화 아이디어를 먼저 구현할 필요는 없다. 운영 배포는 별도 상태로 기록한다.

| 중간 — 저장 상태 재주입 | 같은 파일 `:683–686`에서 인상을 저장하지만 V2 assembler에 characterThought/lastEmotion 읽기가 없다 | 저장한 상태 중 실제 연기에 필요한 것의 읽기 경로를 대조한다. 생성된 추정과 확정 사실의 출처·시점을 구분하며 무조건 재주입하지 않는다 |

이 항목들은 단일 턴 프롬프트 문장을 더 강화해도 입력 자체가 손실되면 해결되지 않는 영역이다. 먼저 무료로 가능한 대화/상태 재현 검사를 만들고, 수정 후 제한된 생성 확인으로 효과를 판단하는 순서를 권한다. 실제 런칭 차단 결함인지 여부는 재현·영향 확인 없이 단정하지 않는다.

다음 우선순위는 아래와 같다.

- **비용·지연·형식의 측정:** mode별 불필요 구획, 안정적인 공통 prefix, 실제 cached tokens, V1의 첫 scene 이전 출력 분량을 각각 측정한다. 이벤트 메타데이터의 선행 계약은 보존한다. 구조화 출력은 해당 OpenRouter endpoint의 지원을 확인하고 스키마·파서·FE를 함께 검증한다. 유효한 JSON이어도 사실·캐릭터성까지 보장되는 것은 아니다.
- **제작자가 승인한 품질 기준:** 서로 다른 개성의 캐릭터2–3명에 대해 ‘원하는 대사/원하지 않는 대사’와 관계 단계별 사례를 소량 확정한다. 이번 E1 실패를 few-shot 전체의 무효로 일반화하지 않되, 예시를 추가하면 좋아진다고 가정하지도 않는다.
- **유지보수성:** 상태 조회와 순수 프롬프트 조립을 분리하고 입력 snapshot·출처·우선순위를 명시한다. 초기 loader/composer 계획은 미실행이다. 먼저 전송본을 유지하는 리팩터링으로 검증하고, 품질 개선과 별도로 평가한다.

## 6. 방법론에 대한 최종 판단

현재의 ‘너는 이 인물이다’라는 역할 지정이 오래됐다는 이유만으로 폐기할 근거는 없다. 현재 프롬프트에는 이미 배경·동기·관계·게임 규칙이 있고 V2는 감독 역할까지 분리한다. Google의 현행 가이드도 역할/핵심 제약·예시·맥락 배치를 설명한다. 다만 이 일반 가이드가 Lucid의 한국어 RP 품질을 보장하는 것은 아니다. [공식 프롬프트 가이드](https://ai.google.dev/gemini-api/docs/prompting-strategies).

향후 형식 안정화에는 [Gemini 구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output)을 참고하되 실제 사용하는 provider/API 계약을 확인한다. 캐시 역시 [OpenRouter 공식 가이드](https://openrouter.ai/docs/guides/best-practices/prompt-caching)가 Gemini 2.5 이상에서 자동 implicit caching과 안정적인 앞부분을 안내하므로, 수동 marker의 존재만으로 캐시 적용/미적용을 판정하지 않는다. 이번 실험에서는 캐시를 통제하지 않았으며 최적화 효과를 입증하지 않았다. 위 문서는 2026-09-22 재확인했다.

추가 모델 탐색, 복잡한 다중 생성 파이프라인, 벡터 검색/학습의 도입은 이번 결과만으로 우선 과제가 되지 않는다. **이번 종료 권고는 수리본 통합·최종 P1 수용 확인 후 구현 범위를 닫고, 다음 품질 과제는 실제 대화 상태·기억 전달의 정확성으로 좁히는 것이다.**
