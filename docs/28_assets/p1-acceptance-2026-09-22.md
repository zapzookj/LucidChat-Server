## 3. 지연과 비용: 자유 모드의 부담은 남는다

TTFS는 첫 토큰이 아니라 **스트림에서 첫 완성 씬을 얻은 시간**이며, 실제 브라우저 렌더링 시간은 아니다. 아래는 중앙값이다.

| 비교 | 표본/후보 | P0 첫 씬 | P1 첫 씬 | P0 전체 응답 | P1 전체 응답 |
|---|---:|---:|---:|---:|---:|
| 자유 핵심 | 8 | 2.80초 | **4.34초** | 4.66초 | **6.23초** |
| 자유 재확인 | 8 | 3.36초 | **3.85초** | 5.18초 | **6.14초** |
| 스토리 핵심 | 8 | 3.07초 | 2.80초 | 8.82초 | 6.77초 |

자유 모드는 합계 16쌍 중 15쌍에서 P1 첫 씬이 늦었고, 재확인 P1에는 13.48초·25.85초의 긴 지연도 있었다. **P1을 속도 최적화로 평가하지 않는다.** 호출 시간대·공급자 변동을 제거한 대규모 시험은 아니므로 원인·운영 지연 분포를 확정할 수는 없지만, 반복된 관측을 단순 노이즈로 무시할 수도 없다.

입력 토큰 중앙값도 자유 8,013→8,888, 스토리 7,141.5→8,185.5로 증가했다. 캐시 적중을 많이 관측했고 출력 토큰은 줄어, 핵심 8회 비용은 자유 $0.02119→$0.02115, 스토리 $0.03527→$0.03231였다. 이는 캐시·출력 길이를 포함한 이번 청구액이며, 콜드 캐시 비용 절감이나 입력 토큰 축소를 입증하지 않는다. [전체 통계](p1-acceptance-2026-09-22/statistics.json)

판단은 **확인된 지시 충돌을 남겨 두기보다 수리를 유지하되, 자유 모드 지연을 잔여 비용으로 명시**하는 것이다. 추가 속도 실험·추론 설정 변경은 사용자가 종료한 탐색 범위를 다시 열기 때문에 진행하지 않았다. 출시 후 실제 TTFS·실패율을 관측한다면 자유 모드 지연을 우선 확인할 가치가 있다.

## 4. 최종 확인에서 발견해 수리한 한 가지

자유 모드 이벤트는 `inner_thought: null`을 요구하지만, 기존 조립기는 이벤트 중에도 일반 속마음 작성 지침을 적재했다. 이 충돌은 수리 전 기반 코드에도 존재했다. 확장 2회 중 1회에서 모델이 속마음을 문자열로 작성해 재현됐다.

`CharacterPromptAssembler`에서 일반 속마음 블록을 **이벤트가 비활성일 때만** 넣도록 조건 하나를 추가했다. 이벤트 종료 후 일반 지침이 복원되고, 이벤트가 아닌 director interlude 및 일반/시크릿 분기 동작은 보존되도록 계약 테스트를 추가했다. 출력 스키마·서버 후처리·과금·상태 전이 정책은 바꾸지 않았다.

동일 입력 4회 재확인에서 `inner_thought: null`, `event_status: ONGOING`, 일반 5스탯 전부 0, 실제 캐릭터 대사 출력을 모두 확인했다. 이는 지시 충돌의 제거와 제한된 재현 확인이며, 확률적 출력의 영구 무오류를 보장하는 서버 강제 장치는 아니다. [최종 코드 독립 검토](p1-acceptance-2026-09-22/final-code-review.md)

## 5. 확장 경로와 남은 한계

- **다른 인물·다인물:** 클레어의 다정한 존댓말, 로제타의 허세·도발, 시에라의 느린 해요체가 구분됐다. 두 인물의 화자 이름과 ID별 5스탯이 맞았다. 다만 처음 만남에서의 빠른 설렘·모든 씬의 속마음은 제작자가 따로 판단할 표현 성향이다.
- **자동 오프닝:** 유저 입력 없이 1–2씬·빈 스탯 계약은 지켰지만, 2회 중 1회에서 사용자에게 ‘잔디의 감촉이 생경하다’는 주관적 감각을 부여했다. 이 명확한 잔여 사례를 핵심 16쌍의 0건에 섞어 숨기지 않는다.
- **연속 3턴:** 이름과 현재 위치/아직 이동하지 않은 상태를 대체로 유지했다. 과거 제안을 가정하거나 사용자 표정을 보태는 작은 서술은 남았다. 실제 DB 상태 갱신·관계 성장·요약/RAG를 거친 장기 기억 시험은 아니다.
- **시크릿:** 비노골적인 차 대화에서 8스탯 분기를 확인했다. 콘텐츠 허용 범위·거절률·모더레이션·성인 인증의 검증 결과는 아니다.
- **시험 입력의 한계:** 클레어는 DAY 상태와 공식 첫 인사의 야간 묘사가 충돌하므로 밤 언급을 모델 오류로 세지 않았다. F04/S02의 괄호 행동은 비표준 스트레스 입력이며, 명시된 행동 표시는 `*...*`다. F08의 합성 복장 기록과 고정 서버 복장도 충돌하므로 복장 상태 준수의 정답 사례로 사용하지 않았다.

확장군에는 P0 대조가 없다. 잔여 현상을 P1이 새로 만든 퇴행으로 단정할 수 없으며, 문제가 없다고 단정할 수도 없다. [확장 의미 검토](p1-acceptance-2026-09-22/extended-semantic-review.md)

## 6. 검증과 종료 범위

최종 코드에서 선택한 Java 계약 테스트 **31건**, Node 비교실·과금·격리 테스트 **107건**, 기존 **13개 후보 smoke**, 확장 fixture **5개 self-test**, `bootJar` 빌드가 성공했다. 생산 JAR에서 실험실 클래스·테스트·Mockito/JUnit·역사 프롬프트 자원이 빠져 있음을 별도 검토자가 확인했다. 전체 애플리케이션 테스트·실제 DB/FE 통합·운영 배포 smoke는 실행하지 않았다.

소스 검토와 비용·데이터 원장 검토는 별도 컨텍스트에 분담했다. [최종 비용 감사](p1-acceptance-2026-09-22/independent-billing-audit.json), [최종 코드 검토](p1-acceptance-2026-09-22/final-code-review.md), [보고서·68건 열람 자료 대조](p1-acceptance-2026-09-22/final-report-review.md), [실행 검증 기록](p1-acceptance-2026-09-22/final-verification.json)을 함께 확인한다. 비교실은 최종 빌드로 재기동했고, HTTP 진입·상태 조회와 두 모드의 실제 Java 프롬프트 미리보기를 과금 없이 확인했다. 이 확인 전후 비용 원장은 동일했다.

**완료:** 모델 선택, 비교실, 제한 예산의 구조 후보 실험, 채택/미채택 결정, 정합 수리, 최종 P1 확인, 원문·정산·검증 기록 보존. **이번에 구현하지 않은 후속 방향:** 긴 기록의 화자·기억 보존, 턴별 상태 공급 구조, 관계 속도·오프닝 서술, 자유 모드 지연 최적화. 초기 구조 계획의 모든 아이디어를 구현 완료했다고 표현하지 않는다.
