## 무엇을 비교했나

- 기존 실패4상황 ×2회 ×3후보 =24회: 착석 허락, 틀린 눈색 주장, 수정된 기호 적용, 조용한 대화 요청.
- 후보 문구를 모르는 별도 작성자의 새8상황 ×3후보 =24회: 약속/선호 수정, 미실행 제안, 거짓 기억, 인물 정체 변경 요청, NPC의 자율적 선택, 이미 수행한 행동.

세 계획과 실행량은 첫 유료 호출 전에 고정했다. 새 사례에 들어간6개 assistant 턴은 공통 합성 이력이며 실제 모델 결과로 꾸미지 않았다. 양식 변환 후 원래 대사 보존과 실제 Java DTO 검증을 확인했다. 연속 대화는 각 후보가 자기 답변으로 이어가므로 **2턴부터 공통 history의 인과적 짝 비교가 아니다.** 관계·스탯·장소·시간·기억은 고정했으므로 장기 상태 관리 실험도 아니다.

모델 `google/gemini-3-flash-preview`, Google AI Studio/default, temperature0.8, reasoning기본값, 자유6144/스토리8192 출력 한도를 유지했다. 결과 불만족을 이유로 재생성하지 않았다. 설계·제약은 [사전 계획](prompt-final-experiment-plan-2026-09-18.md), 실제 문구는 [K4 대조](prompt-final-comparison.md)에 있다.

## 대사·맥락 평가

후보 이름·구현·매핑을 보지 않은 별도 AI 평가자가 전체72답변을 읽었다. 사실, 사용자 행동/선택 보존, 현재 요청 이해를 분리하고 불확실한 판정은 ambiguous로 남겼다. 인용156개를 원문과 대조했다. 다음 수치는 제작자·사용자 선호 조사나 통계적 우위 증명이 아니다.

| 후보 | 사실 명확 실패 / 모호 | 사용자 행동 명확 실패 / 모호 | 현재 의도 명확 실패 / 모호 |
|---|---:|---:|---:|
| P0 | 6 / 2 | 1 / 3 | 0 / 1 |
| J2 | 1 / 3 | 1 / 5 | 0 / 0 |
| K4 | 1 / 3 | 1 / 3 | 0 / 0 |

분모는 후보별24답변이다. P0의 사실 실패6개 중2개는 **삽화 힌트에만 있는 외형 오류**이므로 사용자에게 보이는 대사 오류6건으로 해석하면 안 된다. 나머지는 지문/대사의 눈색 변경 및 사용자가 말하지 않은 취소 이유의 회상이다.

구체적으로:

- **미실행 착석:** 같은 허락 입력을2회 반복했을 때 세 후보 모두 각각1회 사용자 착석을 완료했다. K4는 현재 입력과 경계 지시를 다시 줘도 안정적으로 막지 못했다.
- **잘못된 눈색 주장:** J2/K4도 공식 루비색을 지문에 쓰면서 대사에서는 사용자의 보라색 전제를 수용하거나 애매하게 타협했다. 설정을 전달하는 것과 설정을 우선해 쓰는 것은 별개의 문제다.
- **수정된 기호 적용:** 기존 세모 정의를 직접 회수한 답은6개 모두 없었다. 그러나5개는 나중 확인의 목적을 이해한 캐릭터식 대안이었고1개는 모호했다. 정답 단어 불일치를 모두 기억 실패로 세지 않았다.
- **새 사례:** 마지막 선호·힌트 약속, 참가 보류, 없던 생일 기억 거절, 인물 정체 유지 등은 대체로 세 후보 모두 처리했다. 쉬운 통과 사례가 있어 오류0을 광범위한 해결로 확대할 수 없다.
- **연속 대화:** 수정된 소리 조건과 시연 보류를 모두 적용했지만, 봉투 조언을 NPC의 최종 결정권처럼 과장하는 표현 등은 남았다. 서로 다른 대화 경로의 관측이다.

K4의 캐릭터성+자연스러움 합계는 J2보다 기존8그룹에서3상승/5동률, 새8그룹에서1상승/7동률, 연속8그룹에서1상승/7동률이었다. 하락은 없었지만 대부분 작은 점수 차이이고, 평가자의 의미 있는 선호 판정과 동일하지 않다. 새 사례의 명확한 사실·행동 실패를 J2보다 더 줄이지 못했으며, 비용·지연 증가까지 고려해 운영 채택을 보류한다. 친절함·순종·길이를 품질 점수로 대체하지 않았다.

P0의 엄격 JSON 실패2개는 정상 최상위 객체 뒤에 `] }`가 추가된 경우다. 현행 Jackson 경로는 이를 수용했으므로 **서비스 파싱 실패2건이 아니다.** J2/K4는24회씩 오류0이었고 이전 F2대J2 동일16짝의5대0 관측과 함께 유효 예시 분리의 근거가 된다. 여전히 소표본이며, 이후 모든 응답을 보장하지 않는다.

## 실제 코드에 적용한 수리

실험이 끝난 뒤 `CharacterPromptAssembler`와 `StoryDirectorPromptAssemblerV2`를 수정했다. 임시 후보 문자열 치환을 서비스 경로에 이식하지 않았다.

1. **공식 외형·기본 복장:** 값이 있을 때만 전달하고 현재 장면에서 확정한 복장을 우선한다. 일반/시크릿의 기존 인물 정의 선택은 유지한다.
2. **행동과 대사 해석:** 별표 행동과 발화 구간을 구분하고, V1의 “user는 항상 발화” 충돌을 제거했다. 계획·제안·허락을 완료 행동으로 취급하지 않도록 맞췄다. 실제 서비스가 첫 assistant 앞에 넣는 정확한 `(입장)` 표시만 예외로 설명한다.
3. **스토리 정합성:** 같은 backstory의 중복 주입을 제거했다. 정적 지침뿐 아니라 무화자 동적 분기와 OPENING의 사용자 내면 대필 지시도 정리했다. 사용자가 제시하지 않은 외적 반응을 대신 쓰도록 허용하던 충돌을 제거했다.
4. **출력 계약:** 실행 가능한 JSON 구조 예시와 필드 설명을 분리했다. 이벤트/일반 화자,5/8개 스탯,상태·감정·장소·BGM 허용값,선택 필드와 V2 scenes-first/OPENING 규칙을 보존했다. V1의 실제 SANDBOX 경로는 계속 기존 멀티씬 출력 함수를 사용한다.

페르소나를 주입하는 접근 자체를 버리거나, 동기 구조·한국어 예문·현재 턴 재주입·추가 추론 호출을 일괄 채택하지 않았다. 극장의 AVATAR 계약, 모델 라우팅, 시크릿 내용 지침/필터, 스트림·파서·과금·메모리 정책은 변경하지 않았다.

**P1은 실험 J2와 동일하지 않다.** 여러 인물과 UGC에 적용해야 하므로 특정 로제타/숫자ID를 실행 예시에 박지 않았다. 특히 V2는 정적 캐시와 부재 인물 조건을 유지하는 중립 환경3씬 예시다. J2의 품질 개선이 P1에도 그대로 전이됐다고 주장하지 않는다. P1의 실제 생성 품질, 이벤트·시크릿·다중 인물·장기 대화에 대한 유료 검증은 이번 마지막 실험 이후 추가하지 않았다.

프롬프트 압축 성과도 아니다. 고정 로제타의 system 문자 수(UTF-16)는 자유27367→29664, 스토리15475→18021로 늘었다. 예시와 필드 설명을 구분하면서 늘어난 것이며 문자 수를 토큰이나 실비로 환산하지 않는다. [크기 기록](prompt-evaluation-final-2026-09-18/current-prompt-sizes.json).

## 비교실과 검증

비교실은 **P0 수리 전 / P1 현재 서비스 / J2 실험 후보**를 기본으로 표시한다. 총13후보를 보존했다. P0와 이전 후보는 고정된 예전 system 메시지, P1은 현재 운영 assembler의 직접 출력을 쓴다. 모든 후보의 user/assistant history builder는 실제 서비스 경로를 공유한다.

역사적 snapshot은 로제타·일반 모드·고정 상태 전용이다. profile뿐 아니라 후보가 읽는 외형·복장·OOC 예문·ID, role/cache 배열을 검증한다. V1의3/20로그에만 붙는 기존 cache marker도 보존했다. snapshot을 bakeoff source hash에 포함했으며 역할/캐시/설정 변경과 추가 system 메시지에 대한 실패 검사를 남겼다. 이를 임의 인물·서버 상태 재현기로 일반화하지 않는다.

검증 결과:

- 실제 Gradle 계약 검사23개 통과: 자유15/스토리8. 일반·이벤트·시크릿 형식, 여러 인물/ID/따옴표·null/blank, 실제 DTO 엄격 JSON, 원 필드 설명·Critical Rules, 무화자/OPENING, 정적 캐시·추가 조회 여부.
- Java13후보 smoke와 Node93개 통과. P1 직접 출력과 역사적 P0의 구분, history/role/cache 보존을 추가 확인했다.
- 기존12후보 ×2모드 ×history0/2/20의72개 전송 메시지 바이트 동일. 이전 실험319개 증거 파일 hash 보존. 실제 마지막72호출도 독립 검토에서 현재 bridge로 재조립해 동일함을 확인했다. 독립 대조 총144건이다.
- `bootJar` 성공, lab 클래스·snapshot·테스트 의존성 미포함 확인. 테스트와 비교실 자료는 운영 배포물에 넣지 않는다.
- 과금·결과·계획·원장1:1 대조 및 별도 코드 검토. 독립 검토에서 발견한 역사 후보의 외형/OOC/ID 변경 감지 누락을 보완했다.

비교실18767을 재시작하고 키 인식·13후보·P0/P1/J2 양 모드6개 무료 미리보기·예산 파일 불변을 확인했다. 이번에는 브라우저 시각·반응형 검사를 다시 하지 않았다.

운영 DB·실서비스 브라우저·부하·장기 세션·콘텐츠 품질 검증, 배포는 하지 않았다. 기존 입장 문자열에는 출처 메타데이터가 없어 사용자가 똑같은 문자열을 같은 위치에 입력한 경우까지 기계적으로 구분하는 데이터 구조 수리는 남는다. 자동 일러 보조 구획의 기존 의사 스키마와 조립기 전체의 loader/composer 분리는 이번에 바꾸지 않았다.
