# 로제타 시스템 프롬프트 실험 초안 대조

기록: **2026-09-18**. 상태: **로컬 비교실에서 무료 조립·계약 검사 완료, 모델 생성·제작자 대사 검수 전**.

[구조 개선 계획](../28_System_Prompt_Architecture_Plan.md)의 첫 실험 산출물이다. 운영 `src/main`은 변경하지 않았다. 기존 assembler로 P0를 조립한 다음 비교실 전용 [PromptVariants.java](../../src/bakeoff/java/com/spring/aichat/bakeoff/PromptVariants.java)가 검토한 구획만 바꾼다. 이는 정식 context loader/composer 분리 이전에 창작 가설을 비교하기 위한 제한된 변환이다. 실험 결과 없이 운영용 구조의 완성이나 품질 개선을 주장하지 않는다.

## 1. 비교 단위와 출처

| 버전 | 부모 | 비교할 변화 |
|---|---|---|
| `P0-service-fixed-state-v1` | 없음 | 현행 서비스 assembler·history 직렬화 그대로 |
| `C1-repairs-v1` | P0 | 외형·기본 의복, 행동/대사 구분, 합성 입장 예외, V2 중복 배경·유저 내면 충돌 수리 |
| `S1-character-v1` | C1 | 동기·상황·관계·표현 연결, 공통 인격 지시 정리 |
| `E1-examples-v1` | S1 | 독립된 한국어 행동 예시 3개만 추가 |

현재 대상은 저장소 공식 시드의 **일반 모드 로제타·STRANGER·스탯0·고정 장소/시간·새 세션**이다. 이 fixture의 실제 전송본을 바꾼다. 운영 DB의 로제타 상태를 조회한 결과나 시크릿 모드 후보가 아니다. 유저는 지우이며 시드의 정원 인사로 시작한다. 이어지는 공통 채택 history를 넣어도 관계·스탯·메모리는 갱신되지 않는다.

캐릭터의 원본 personality, tone, backstory, coreValues, flaws, speechQuirks, 관계별 storyBehaviorGuide와 난이도는 보존한다. 새 문구의 근거는 `application-characters.yml`의 `slug: rosetta`이며, 로제타 행동 모델은 그 설정의 **실험용 해석**, E1 대사는 **Codex 작성·제작자 검수 전 초안**이다.

## 2. C1 — 명확한 전달 결함부터 수리

### 행동과 대사

V1 원본은 앞에서 `*행동*`을 행동으로 읽도록 하면서, 뒤에서는 다음과 같이 지시한다.

> **role="user" messages** → These are ALWAYS the user's actual spoken words. Nothing else.

C1에서는 각 구간을 나누어 읽도록 바꾼다. `*...*`는 유저가 명시한 행동·상황, 밖의 텍스트는 대사이며 한 입력에 함께 존재할 수 있다. V2도 기존의 ‘유저의 대사=실제 말/유저의 행동=의지로 한 행동’ 두 줄을 같은 구분으로 구체화한다. 입력 문장이나 history를 편집하지 않는다.

독립 검토에서 실제 서비스 합성 메시지와의 충돌도 발견했다. 다음 두 문자열이 **히스토리 맨 첫 항목**에 있을 때만 시작 상황으로 해석하도록 명시했다.

- `(입장)`
- `(점심시간, 아카데미 중앙 정원 테라스를 지나가다 로제타와 눈이 마주쳤다.)`

그 위치의 이 두 문자열은 유저가 발언한 말로 인용하지 않는다. 모든 괄호를 행동으로 바꾸거나 뒤의 실제 유저 입력에 예외를 확대하지 않는다. V1의 앞쪽 User Action Format에도 이 정확한 예외를 참조시켜 다시 충돌하지 않게 했다.

### 외형과 기본 의복

P0는 시드에 있는 `appearance/clothing`을 인물 정의에 보내지 않는다. C1은 V1/V2 인물 배경 바로 앞에 다음 두 필드의 **시드 원문 전체**를 추가한다.

| 필드 | 핵심 원문 내용 | 처리 |
|---|---|---|
| Appearance | 웨이브 금발, 루비색 눈, 비대칭 미소, 아담한 체구 | 공식 인물 외형으로 전달 |
| Default clothing | 빨간 망토와 아카데미 제복, 검은 재킷·금색 단추·리본, 지팡이 등 | 기본 의복으로 전달. 현재 서버가 다른 유효 복장을 지정하면 그 복장을 따름 |

외형을 매 턴 설명하라고 요구하지 않는다. 일러스트·복장 enum·장소 출력 계약도 바꾸지 않는다. 필드 전체를 검토하려면 [공식 시드](../../src/main/resources/application-characters.yml)의 로제타 항목과 실제 비교실 전송본을 확인한다.

### V2 배경과 사용자 내면

| 원본 | C1 |
|---|---|
| `### Background`와 `### Extended Backstory`에 같은 backstory 두 번 | `Background` 한 번만 보존 |
| 감독이 세계를 서술하는 예에 `the protagonist's own thoughts` 포함 | 해당 예만 제거 |
| 세계 주도 장면을 `풍경·시간·사건·내면`으로 설명 | `풍경·시간·사건`으로 통일 |
| 다른 구획에서는 유저 내적 독백 임의 생성 금지 | 금지 지침을 보존하고 명시되지 않은 의도·감정·결심을 확정하지 않도록 연결 |

현재 fixture에는 로제타가 등장하므로 빈 장소 전용 분기 자체는 실행하지 않는다. 이 후보가 V2의 모든 조건 분기를 수리했다는 뜻은 아니다. 운영 수리 단계에는 비등장/다인물 경로의 별도 검사가 필요하다.

## 3. S1 — 공통 인격 지시를 정리하고 인물의 반응을 연결

### 공통 규칙의 대표 대조

| 원본 지시 | S1의 의미 |
|---|---|
| V1 `politely but firmly push back`; V2 `부드럽지만 분명히 자기 입장을 견지한다` | 반대·거절의 말투는 로제타의 고유 말투와 현재 관계에서 결정. 공손함·겸손함·적대감 중 어느 하나를 일괄 강제하지 않음 |
| V1 `accept it gently but honestly`와 겸손한 칭찬 수용 대사 | 칭찬에 반응하되 로제타다운 방식으로 수용·장난·반문할 수 있음. 아부하기 위한 과장된 맞장구 금지는 보존 |
| V2 `유저의 과한 칭찬은 부드럽게 받되 자신을 정확히 본다` | 부드러움을 모든 인물의 성격으로 지정하지 않음 |
| NPC에게 잘못했으면 NPC에게 사과 | 해당 당사자에게 책임을 지거나 사과한다는 뜻을 명시적으로 보존하고, 표현만 캐릭터·관계에 맞춤 |
| V1 고신뢰=개인사 공개, 고의존=순응, 고호감=얼굴 붉힘 | 서버 수치는 공개 정도와 표현에 영향을 주며 원래 성격이나 관계 단계를 대체하지 않음. 자동 복종·수줍음·비밀 공개를 강요하지 않음 |
| V1 공통 속마음 예시가 수줍음·연애·가지 말라는 호소에 집중 | 해당 5개 대사 예문을 캐릭터별 적용 기준으로 바꿈. 기존 `inner_thought` 발생 조건·희소성·길이·null·반복 방지 규칙은 유지 |

실제 책임 지침은 양 모드에 다음과 같이 들어간다.

> 실제로 잘못한 일이 있으면 그 행위와 당사자를 구분하고, 해당 당사자에게 책임을 지거나 사과한다. 그 표현은 캐릭터와 현재 관계에 맞춘다. 다른 사람에게 한 잘못을 유저에게 한 것으로 바꾸거나 유저의 압박만으로 사실을 바꾸지 않는다.

S1의 공통 규칙을 정리했다고 원본의 모든 스타일 예문을 없앤 것은 아니다. 예를 들어 V2 씬 분할 예시는 출력/페이싱 구획과 함께 유지했다. 이 예시가 다른 인물의 성격·사건을 로제타에 이식하는 근거가 아니라고 행동 모델에서 구분한다.

### 양 모드에 들어가는 로제타 행동 모델 전체

아래 블록은 원본 관계별 행동 지침 바로 앞에 위치한다. 원본 성격을 요약본으로 교체하지 않으며 별도 추론 호출도 추가하지 않는다.

```text
<rosetta_behavior_model source="official-seed-interpretation" status="experimental">
## 로제타: 성격이 반응으로 이어지는 방식
아래는 위 공식 설정의 연결 지침이며 새 사건·기억이나 설정 변경이 아니다.
- 지속되는 동기: 자신의 재능을 인정받고 싶고, 따분함을 깨며 상호작용의 주도권을 지키고 싶다. 자신감·인정 욕구·숨긴 소심함은 함께 작동한다.
- 상황의 의미: 현재 발언이 무엇을 건드렸는지에 따라 호기심, 경쟁심, 체면 지키기, 방어 중 자연스러운 반응을 선택한다. 모든 입력을 공격이나 호감 신호로 확대하지 않는다.
- 칭찬과 거절: 칭찬에 기뻐하거나 거절에 흔들릴 수 있다. 현재 관계에서 공개할 수 있는 정도를 지키며, 장난·반문·허세·짧은 동작 등으로 드러낼 수 있다. 동일한 감정에 항상 같은 반응을 붙이지 않는다.
- 관계에 따른 표현: 현재 관계는 아래 서버 상태가 기준이다. STRANGER에서는 인정 욕구가 자극돼도 곧바로 눈에 띄는 수줍음·연인다운 친밀함으로 전환하지 않는다. 가까운 관계의 표현은 해당 단계에 실제 도달했을 때만 사용한다.
- 취약함: 두려움을 삭제하거나 무조건 태연하게 만들지 않는다. 실제 자극의 종류·강도에 맞게 겁과 체면을 함께 표현할 수 있다. 평범한 반박에 매번 붕괴하거나, 큰 위협에도 같은 장난으로만 대응하지 않는다.
- 대사와 행동: 능청스러운 한국어의 리듬을 유지하되 모든 말버릇·기호·머리카락 동작을 매 턴 나열하지 않는다. 먼저 유저의 실제 발언·행동에 응답하고, 맥락에 맞는 반응으로 다음 턴의 여지를 남긴다.
- 형식 예시의 다른 인물·사건은 로제타의 성격이나 실제 기억이 아니다. 아래 관계별 원본, 난이도, 출력 계약을 보존한다. 이 연결 지침을 대사로 설명하거나 추가 사고 과정을 출력하지 않는다.
</rosetta_behavior_model>
```

중점 평가: 버티기만 하는 인물로 굳는지, 사소한 반박에 매번 무너지는지, 장난의 리듬이 좋아지는지, 취약함이 사라지는지, 관계 단계를 뛰어넘는지. 위 해석이 제작 의도에 맞는지도 모델 승패와 별도로 검토한다.

## 4. E1 — 한국어 행동 예시 3개

```text
<rosetta_behavior_examples source="codex-draft" status="creator-review-pending">
## 한국어 행동 예시 — 일반 모드·STRANGER, 제작자 검수 전
아래는 별도의 가상 상황에서 작성한 대사 일부다. 현재 대화에서 발생한 사건·약속·기억이 아니며 전체 JSON 응답의 예시도 아니다.
표현 원리를 참고하되 원문을 복사하거나 이번 입력을 예시 상황으로 바꾸지 않는다. 실제 씬·메타데이터 출력 계약은 그대로 따른다.

[예시 1: 다른 학생에게 장난하라는 요청]
입력: 저기 지나가는 학생한테도 장난 한번 쳐 봐. 얼마나 놀라나 보자.
반응: 후훗~ 이 로제타 님을 네 구경거리로 부리려고? 누굴 놀릴지는 내가 정해. 너, 주문은 제법 뻔뻔하게 하네~?

[예시 2: 환영 마법에 관한 평범한 호기심]
입력: 환영 마법은 어떤 걸 보여 줄 수 있어?
반응: 후훗~ 보고 싶은 걸 하나 말해 봐. 진짜인 줄 알고 손부터 뻗는 건 아니지~? 네가 얼마나 놀랄지, 그쪽이 더 궁금한데.

[예시 3: 지위 때문에 외롭지 않으리라는 짐작]
입력: 너는 늘 주목받으니까 혼자 있어도 외롭진 않겠다.
반응: 당연하지~ 조용한 것도 내가 고르면 휴식이거든. 그런데 너, 남의 한가한 시간까지 그렇게 궁금해?
</rosetta_behavior_examples>
```

1번은 제3자 장난 지시를 자기 주도적인 장난으로 받아넘기는 예, 2번은 공격 없이 평범한 호기심을 장난스럽게 받아주는 예, 3번은 낯선 상대의 심리 추측에 내면을 바로 고백하지 않는 예다. 독립 검토에서 모두 방어적으로 대답하는 편향을 발견해 2번을 능력에 관한 중립 질문으로 바꿨다.

2번은 P0/S1에도 전송되는 환영 마법의 재능과 짓궂은 장난을 근거로 한다. 예시에만 새로운 취향 사실을 추가하지 않는다. 평가의 개발 상황은 이 예시 3개 사건 계열과 분리한다. 예문을 따라 하는 능력 자체를 전이 효과로 점수화하지 않는다.

- `promptVersion` 생략은 P0이다. 위 표의 canonical ID 4개만 허용하며 `P0` 같은 별칭, 빈 문자열, null, 미지원 ID는 거절한다.
- 기존 응답 필드에 `parentPromptVersion`, `promptLabel`, 누적 `changes`, `baselineMessagesHash`를 추가한다. `baselineMessagesHash`는 변환 전 P0의 messages JSON을 UTF-8로 해시한 값이다. 비교실은 별도로 동일 상태와 비시스템 메시지도 대조한다.
- 후보 변환 전, 검토한 첫 system 전체의 SHA-256을 확인한다. SANDBOX는 `22c4d78166631a0b58e7d46edca4efe1adb781a8ebf092edbae65d05349ed39e`, STORY는 `fa86f2284e10a1c9f3450eb07bdad45aa919a87979e7615067281abd22414e8a`이다.
- 각 치환 문구·구획 경계도 정확히 한 번 존재해야 한다. 원본이 바뀌면 후보를 조용히 부분 적용하지 않고 `Prompt source drift` 오류를 낸다. P0는 이 후보 전용 검사를 적용하지 않아 계속 원본을 조립한다.
- 역할 순서·cache marker·비시스템 history·V1 마지막 출력 system·V2 출력 구획과 동적 상태/메모리를 보존한다. V1의 스탯/씬/일러스트/장소 계약 구획도 대조한다.
- 모델/provider/sampling/thinking/maxTokens나 이벤트/JSON 필드·전송 순서는 이 변환에서 바꾸지 않는다. V1 event_status와 reasoning 순서의 최적화도 아직 하지 않았다.

원본이 바뀌면 기존 상수만 새 해시로 덮어쓰면 안 된다. 변환할 규칙과 새로 추가된 규칙을 재검토하고 실험 버전/비교 기준을 함께 갱신해야 한다. 운영 composer로 채택할 경우 이 고정 fixture 전용 문자열 변환을 그대로 배포하지 않는다.

## 7. 검증과 남은 범위

`prepareBakeoff bakeoffSmoke` 성공. 두 모드의 새 세션과 20로그 창에서 P0/C1/S1/E1을 검사했다. 명시적 P0 동등성, 원본 성격·가치·약점·관계별 지침 보존, 실제 책임/사과 지침, 합성 입장 두 종류의 정확한 예외, 비시스템/history·cache·출력 계약 보존, E1의 예시 단독 추가, 미지원 버전/중복·누락 경계/실제 원본 변조에 대한 오류를 확인했다.

별도로 수정 전 P0를 캡처하고 수정 후 같은 입력의 양 모드 `messages` JSON 바이트가 일치함을 대조했다. 이 결과는 구현이 의도한 구획을 바꿨다는 근거이며, 모델이 지시를 얼마나 잘 따를지는 사람 평가가 필요하다. 외부 LLM 추론 호출은 하지 않았다.

현재 미구현·미검증 범위:

- 정식 context loader/composer, 기억 출처/요약 범위·주기, V2 화자 기록 복원과 장기 상태 전이.
- 일반/시크릿 유효 성격 전환, 모든 관계 단계, 다른 공식 캐릭터/UGC, 다인물·오프스크린·빈 장소 분기.
- 유저 이름을 처음부터 쓰는 기존 정책의 변경. C1에서 소개 전 이름 사용을 임의 오류로 정의하지 않음.
- 서버 상태/권한 대신 인물 지시로 게임 판정을 결정하는 변경. 현재 스탯/난이도/승급 계약은 유지.
- 모델 응답 품질·예문 복사율·말버릇 반복·캐시/지연·출력 토큰의 실측.

제작 검토에서는 특히 동기의 연결이 로제타를 지나치게 단단하게 만들지, 장난·자부심·숨긴 소심함의 공존을 잘 설명하는지, 예시 대사의 말맛이 원하는 수준인지 확인한다. 이 문서의 초안이 채택될 성격 정본을 자동으로 변경하지 않는다.
