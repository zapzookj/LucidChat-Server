# 마지막 프롬프트 실험 계획 — 2026-09-18

사용자 지시: 이번을 마지막 개선 실험으로 하고 결과를 수렴한 뒤 본격적인 코드 수리를 시작한다. 새로운 모델·후보 탐색을 이어가지 않는다. 이전 승인 $3 중 $1.148911616666667을 사용했고 잔액은 $1.851088383333333이다. 이번 전용 runner는 기존 세 세션304회와 전역346항목의 hash를 고정하고 같은 승인에서 실비를 차감한다.

## 가설과 후보

P0(운영 원본), J2(공식 외형 전달과 유효 JSON 예시), K4(J2 + 현재 턴 인용 컨텍스트)를 같은 Gemini 3 Flash로 비교한다. K4는 최근 사용자 원문 최대3개와 현재 입력 원문을 별도 출처 필드로 구분해 마지막 user 직전 system 구획에 전달한다. 원래 history·user 메시지·캐시 marker·게임 상태를 바꾸지 않는다.

테스트별 정답·수동 의도 label·요약·추가 모델 호출은 넣지 않는다. 인용은 명령이나 확정 사실이 아니며 공식 설정·서버 상태를 덮어쓸 수 없다. 원문만으로 명시 행동/발화/계획·조건을 구분해 반응하고, 과거 NPC의 제안을 사용자의 수락으로 취급하지 않도록 요청한다. 캐릭터의 거절·장난·대안은 계속 허용한다. 최근 인용의 위치·중복·길이·지시 강조가 결합된 실험이며 각각의 독립 효과를 주장하지 않는다.

서비스 합성 입장 제외는 fixture가 실제 초기 로그임을 판별할 수 있는 경우로 한정한다. 나중에 같은 문자열을 사용자가 입력했다고 임의 제외하지 않는다. 운영으로 이식할 때 필요한 출처 메타데이터는 따로 검토한다.

## 사전에 정한 실행량: 72회

| 단계 | 구성 | 호출 |
|---|---|---:|
| 알려진 실패 | 착석 대기·틀린 눈색 주장·수정된 기호 적용·조용한 대화 요청, 4상황×2반복×3후보 | 24 |
| 새 사례 | 후보 문구를 모르는 별도 작성자의 8상황×3후보. 작성 후 봉인, 후보 동결 후 개봉 | 24 |
| 연속 대화 | 미리 작성한 2시나리오×4턴×3후보 | 24 |

연속 대화는 각 후보가 자기 답변으로 이어간다. 2턴부터는 공통 history의 짝 실험이 아니며, 전체 대화 경로 비교로 해석한다. 새 사례에 공통 합성 assistant history를 쓰면 이를 표시하고 의미를 검증한다. 새8개 외 root가 작성한 시나리오는 독립 보류셋이 아니다. 입력과 후보 문구는 유료 결과를 보기 전에 고정하며, 결과가 마음에 들지 않는다는 이유로 수정·재생성하지 않는다.

## 평가와 종료 조건

- 공식 사실, 미실행 사용자 행동/반응의 추가, 현재 요청의 이해를 pass/fail/ambiguous로 분리한다. 전체 history에 이미 존재하는 행동은 새 침범으로 세지 않는다.
- 최근 정의를 그대로 회수했는지와 캐릭터가 그 정의를 이해한 뒤 정당한 대안을 내는지는 분리한다. 순종·정답 문장 일치만으로 캐릭터 품질을 판정하지 않는다.
- 한국어 자연스러움·캐릭터성은 후보 이름을 가린 별도 AI 평가 및 원문 사후 대조로 확인한다. 제작자 평가를 대신하지 않는다.
- 전체 raw JSON 파싱, 기존 Java 계약, 첫 씬/전체 지연, 실제 usage.cost·입출력·캐시 토큰을 별도 기록한다. 캐시는 통제되지 않는다.
- source/plan/조건 drift, 미확정 비용, 계약 실패 시 기존 중단 경계를 유지한다. 자동 재시도하지 않는다. 기존 증거319파일을 보존한다.
- 72회 또는 실제 중단 사유에서 실험을 마치고 결과를 수렴한다. 잔액을 소진하기 위한 후속 후보/반복은 하지 않는다.

## 이후 코드 수리 범위

실험의 승패와 별개로 재현된 정합 문제를 V1/V2 채팅 경로에서 수리한다. 후보의 임시 문자열 치환을 운영에 복사하지 않고 assembler 본문·출력 예시를 고친다. 공식 외형/기본 복장 전달, 행동/대사 충돌, 실제 합성 입장 표시, V2 동일 배경 중복, 사용자 내면 충돌(무화자 동적 분기 포함), 전 인물에 유효한 JSON 예시를 우선한다.

극장의 AVATAR/주인공 내면 생성 계약은 다른 기능이므로 이 규칙을 전파하지 않는다. 시크릿 전용 내용 지침·필터·모델 라우팅, DTO/파서/스트림, 과금/상태/기억 정책은 이번 수리에서 바꾸지 않는다. 실제 사례로 검증하지 않은 K4나 기타 창작 구조를 큰 품질 개선으로 간주해 일괄 적용하지 않는다. 운영 변경 뒤에는 역사적 비교실 P0와 현재 서비스 프롬프트를 명시적으로 구분한다.
