# 15. 로비 재설계 지시서 — 블록 A 프론트 전면 재구성 (2026-08-14)

> 선행: [`14_ProductDecisions_Session_Handoff.md`](14_ProductDecisions_Session_Handoff.md) §B(로비 결정) · [`14_assets/lobby_wireframes.html`](14_assets/lobby_wireframes.html)(구조 와이어프레임 — **시각 정본 아님, 구조 힌트일 뿐**)
> **이 문서는 블록 A 프론트의 재설계 정본이다.** 1차 구현(FE `0d9f87b`+`70d5e93`, 미푸시)은 종원 UX 리뷰에서 반려됨 — 와이어프레임을 그대로 갖다 붙인 수준이라 재설계한다. 백엔드(게스트 API·피드·게스트 DTO — BE `3115edc`/`6809945`/`af4d9e8`, 미푸시)는 **유효하니 재사용**하되, 아래 원칙에 따라 응답 필드/네이밍이 바뀌면 함께 조정.

## 0. 작업 방식 (다음 세션 필독)

- **역할**: 구현자가 곧 시니어 UX/UI 디자이너다. 종원은 UX 설계 경험이 적어 디테일 지시를 주기 어렵다 — "깔끔·세련·유저 친화"의 판단을 구현자가 주도한다.
- **와이어프레임은 구조 힌트지 시각 스펙이 아니다.** 그대로 옮기지 말 것. 간격 리듬·타입 스케일·컴포넌트 폴리시·빈 상태·모션 절제를 실제로 설계할 것.
- **디자인 아티팩트 먼저**: 착수 전 목업(HTML 와이어프레임 또는 실제 컴포넌트)을 만들어 종원 컨펌 → 구현. 텍스트 설명만으로 추천 금지(1차 세션 교훈: 목업 없이 "라우트 이동안"을 추천했다가 목업 만들고서 번복함).
- **디자인/UX 적대적 리뷰 필수**: 구현 후 시각·반응형·정보구조·카피 관점의 적대적 리뷰를 돌려 확정 결함을 수정.
- **모델 고정 권장**: 세션 내 자동 모델 전환(안전장치 오탐)이 결과 일관성을 해쳤을 개연성 — 재설계 세션은 모델을 하나로 고정하고 시작.
- 종원 확인 환경: **웹(데스크톱) UI** 기준으로 봤고, AWS 정지로 **에셋 없는 상태**로 확인함. 데스크톱 폴리시를 특히 신경쓸 것(1차는 모바일 우선으로 데스크톱이 부실).

## 1. 종원 지적 원문 (2026-08-14)

1. **홈 피드 필터 탭(전체/공식/UGC/남캐)**: ①'남캐' 탭은 왜 있는지 모르겠다 — 회원가입 시 성별/이름을 입력(또는 소셜에서 가져와)받아 **유저 성별에 맞는 캐릭터를 기본 노출**하는 게 자연스럽다. ②'공식/UGC' 네이밍이 비친화적 — 초심자는 "공식은 뭐고 UGC는 뭐여?" 한다.
2. **감성 네이밍 과함**: 정거장·인연·세계관 등 개발자/하드코어 유저만 알아들을 네이밍이 많다. 특히 캐릭터를 '인연'이라 부르는 건 언어적 진입장벽이 크다.
3. **레이아웃 좌측 치우침**: '세계관에서 시작하기'의 월드들, 보관함 '기억의 끈' 등이 왼쪽으로 쏠려 안 깔끔.
4. **모드 진입 플로우(자유/스토리/극장)**: 정거장=자유, 세계관=스토리+극장 구조인데 비친화적. 초심자는 "정거장·세계관·스토리·극장이 뭐고 서로 뭐가 다른지" 모른다. **정거장 캐릭터 클릭→자유채팅은 직관적이라 OK**, 나머지가 나쁨.
5. **일관성 부족**: ①스튜디오만 별도 페이지 렌더(공간 연출 효과는 있으나 UX 이득 불확실). ②보관함의 페르소나(중앙 모달)/업적(좌측 드로어)/일러스트(별도 페이지)가 **표현 방식이 제각각**.
6. **총평**: 와이어프레임을 그대로 붙인 느낌, 심지어 와이어프레임보다 못한 부분도.

## 2. 재설계 원칙 (지적의 디자이너 관점 재해석 — 다음 세션의 설계 근거)

### P1. 분류(taxonomy) → 개인화(personalization)
- 홈 피드의 필터칩 세금(공식/UGC/남캐)을 **기본적으로 제거**. 대신 온보딩/프로필의 유저 성별을 받아 **취향 맞춤 정렬**로 첫 화면을 구성(예: 유저 성별의 대상 캐릭터 우선). 성별은 회원가입/소셜에서 취득, 미상이면 중립.
- 필터가 필요하면 **기능 언어**로: "추천 / 새로 나온 / 인기"처럼. '공식/UGC' 구분은 필터 축이 아니라 **카드 위 은은한 출처 배지**로 강등(창작자 생태계 노출은 유지하되 초심자에게 분류를 강요하지 않음).
- 성별 취득 UX는 온보딩('첫 만남') 또는 프로필에 얹는다 — **블록 B(페르소나) 성별 필드와 배선 공유** 가능(중복 구현 금지, 블록 B와 조율).

### P2. 네이밍 — 브랜드 1겹 + 기능 언어 우선
- 감성 네이밍은 **한 겹만** 유지(브랜드 보이스). 모든 **기능 라벨은 평이한 말이 1순위**.
- '인연'은 정보 맥락(피드 섹션 제목·카운트)에서는 **'캐릭터'**로. 감성 표현은 카피(부제·배너 문구)에서만.
- 탭 라벨을 기능으로 재검토: 정거장/세계관/스튜디오/보관함 → 초심자가 한눈에 뜻이 잡히는지 테스트. 최소한 각 탭에 **1줄 기능 설명**을 붙이거나, 감성어와 기능어를 병기.
- 모드명(자유/스토리/극장)은 **"당신이 무엇을 하는가"로 즉시 설명**하는 카피를 카드/진입점에 붙일 것(예: 극장="지켜보는 이야기", 스토리="함께 겪는 서사"). 추상 명사 단독 노출 금지.

### P3. 레이아웃 — 중앙 정렬·일관 그리드
- 전 섹션 **max-width 컨테이너 + 중앙 정렬**. 캐러셀·리스트가 좌측으로 흐르지 않게(1차의 좌측 치우침 원인: 컨테이너 폭·정렬 규칙 부재).
- 간격 리듬·타입 스케일을 **디자인 토큰으로 통일**(섹션 여백·카드 갭·헤딩 크기 일관). 데스크톱에서 넓은 여백을 방치하지 말고 그리드 열 수를 폭에 맞게.

### P4. 진입 플로우 — 초심자에게 모드 분류를 강요하지 않기
- **캐릭터 우선 진입은 유지**(정거장 카드 클릭→자유채팅, 종원도 OK 판정).
- 스토리/극장은 **추상 탭으로 먼저 제시하지 말고**, 캐릭터/세계관 맥락 안에서 "이 캐릭터로 할 수 있는 것"으로 노출하거나, 차이를 카피로 명확히. IA에서 '세계관' 탭이 곧 '스토리/극장 입구'라는 연결을 초심자가 스스로 알 수 없다 — 명시적 안내 필요.
- 온보딩 '첫 만남'과 홈의 관계를 매끄럽게(빈손 신규만 온보딩, 이후 홈).

### P5. 표현 일관성 — 보조 표면 1체계
- 보관함의 **페르소나/업적/일러스트를 하나의 표현 패턴으로 통일**(전부 인탭 섹션 or 전부 드로어 or 전부 모달 — 하나 선택). 현행 중앙모달/좌드로어/별도페이지 혼재는 금지.
- 스튜디오 별도 페이지 vs 셸 임베드 재검토: 2안(임베드) 확정이었으나 1차 구현이 어정쩡(자체 크롬 잔존). **임베드로 갈지 풀페이지로 갈지 결정하고 전 표면에 일관 적용.**

### P6. 시각 완성도 (와이어프레임 답습 탈피)
- 빈 상태·로딩 스켈레톤·에러·호버/포커스·모션을 실제 디자인. 모션은 절제(1차의 탭 전환 이중 페이드 같은 회귀 방지).
- 데스크톱·모바일 양쪽을 실제로 검수(1차는 모바일 편중, 데스크톱 탑바 오버플로우 등 발생).

## 3. 재사용 vs 폐기

- **재사용(백엔드, 미푸시 master)**: 게스트 브라우징 permitAll·게스트 DTO 스코프·IP 리밋(`3115edc`/`6809945`/`af4d9e8`), 홈 피드 API(`/lobby/feed`), 세계관 UGC 공개 API(`/lobby/worlds/ugc`), 업적 유저스코프(`/achievements/gallery`). **단** 피드의 배지/필터가 개인화로 바뀌면 응답 필드 조정, 피드 정렬에 유저 성별 파라미터 추가 검토.
- **폐기·재설계(프론트, 미푸시 master)**: `src/pages/lobby/*`(LobbyShell·HomeTab·WorldsTab·ArchiveTab·FirstMeetPage·lobbyShared)·`GuestLoginGate`는 구조 참고만 하고 시각·IA·카피 전면 재설계. 딥링크 복원(`postLogin`)·인트로 페이드 픽스·데드코드 삭제는 유효하니 보존.
- **주의**: 1차 구현은 전부 **로컬 커밋·미푸시**라 되돌리기 부담 없음. 재설계 결과로 대체 커밋하면 됨.

## 4. 열린 결정 (다음 세션이 종원과 확정)

- 유저 성별 취득 지점(온보딩 vs 프로필 vs 소셜 스코프) — 블록 B와 조율.
- 탭 라벨 최종안(감성 유지 정도).
- 보관함 통일 패턴(인탭/드로어/모달 중).
- 스튜디오 임베드 vs 풀페이지 최종.
- 개인화 정렬 규칙(성별 매칭 + 향후 인기지표).
