1. 황금샷(WF-1).
2. Qwen 자세 편집 → Qwen 배경/조명 편집 → WF-2 + FaceDetailer → 사용자가 neutral 스탠딩 선택.

### 2.2 문제에 연결되는 설계

- **과한 동작을 생성하는 지시가 실제로 있다.** 기본 angry는 양손 허리/팔꿈치 벌림, panic은 양손 흔들기이며 WF-2에는 `motion lines`도 들어간다. 동적 연출 LLM은 캐릭터별 표정/상반신 제스처를 각각 영문 20단어 이내로 생성한다. 현재 채택 검사는 유효 키·빈 문자열 중심이고 단어 수/제스처 강도를 실행 시 보장하지 않는다.
- **다른 두 모델이 같은 표정을 다시 해석한다.** Qwen의 동적 표정 지시와 WF-2/FaceDetailer의 고정 감정 태그가 서로 다를 수 있다. 후자는 외형 태그, persona 태그, 감정 태그도 함께 받는다. 섬세한 표정을 만든 뒤 별도 태그로 다시 그리는 단계에서 표정이나 얼굴 길이가 바뀔 가능성이 있다.
- **감정 컷은 좋은 neutral보다 재생성 단계가 한 번 더 많다.** WF-2 KSampler denoise `0.4`, FaceDetailer denoise `0.4`, detail LoRA `0.6`이 템플릿 기본값이다. 두 denoise를 더한 수치로 해석하면 안 되지만, 전신 리파인과 얼굴 인페인트를 각각 수행하는 사실은 중요하다. 실제 배포 override는 미확인이다.
- **리롤은 같은 연출을 다른 seed로 다시 실행한다.** 캐릭터별 연출은 잡에 저장되며 리롤에서 다시 작성하지 않는다. Qwen seed는 바뀌지만 WF-2와 FaceDetailer seed도 매번 새로 정해진다. 잘못된 연출/후처리 조건이 있다면 리롤만으로 해결되지 않는다는 사용자 관찰과 양립한다.
- **성별 지시도 확인 대상이다.** Qwen 템플릿의 `she/her` 문구는 남성 빌더에도 적용된다. 주요 품질 원인으로 확정할 수는 없으며 비교 실험에서 성별 중립 지시를 포함한다.

### 2.3 개선 제안

- 기본 감정 파생은 **자세 고정 + 짧은 표정 지시**로 시작한다. 눈/눈썹/입의 핵심 변화 1~2개만 지정하고 얼굴 외곽, 고개 방향, 손, 어깨, 체형, 구도는 유지한다. 과장된 연기는 기본값보다 선택 가능한 후속 기능이 적합하다.
- 캐릭터 개성은 우선 표정 강도/입꼬리/시선의 작은 차이로 반영한다. 풍부한 손동작을 각 감정의 필수 조건으로 두지 않는다.
- 감정 파생과 neutral용 후처리를 구분한다. 감정 컷의 WF-2를 그대로 공통 사용해야 한다는 전제를 실험으로 확인한다. raw 편집본, WF-2만 적용한 결과, FaceDetailer까지 적용한 결과를 나란히 평가한다.
- 모델이 국소 편집을 충분히 잘하면 감정에 한해 WF-2/FaceDetailer를 생략하고 누끼 단계로 갈 수 있다. 현재 neutral의 화풍과 피부/선화가 유지되는지가 조건이다.
- 고정 seed만으로 정체성 보존을 보장하지 않는다. 중간 산출물·실제 프롬프트·모델/파라미터·모든 단계 seed를 비교에 남긴다.

## 3. Ideogram 4.5 Edit 평가

### 3.1 공식 계약과 비용

현행 fal 인프라에서 `ideogram/v4.5/edit`를 사용할 수 있다. `image_url` 단수 계약이며 Qwen의 `image_urls` 배열 계약과 다르다. Qwen 요청의 모델명만 바꿔서는 연동되지 않는다.

**`edit_precision: high`와 `quality: high`는 별개다.** 기본 edit precision은 `regular`; 변경되지 않은 픽셀 복원을 사용하는 Precise Edit는 `high`를 명시해야 한다. 참조 이미지·선택 마스크를 지원하며 마스크는 검정 편집/흰색 보존이다. 출력은 `auto`에서 원본 geometry를 따르되 공급자 제한에 따른 축소가 가능하므로 실제 치수를 확인해야 한다.

| 모델/품질 | 1장 편집 비용 | 감정 14장 편집 비용 |
|---|---:|---:|
| Qwen 현행, 1024×1024 가정 | 약 $0.03146 | 약 $0.4404 |
| Ideogram Very Low | $0.008 | $0.112 |
| Ideogram Low | $0.03 | $0.42 |
| Ideogram Medium | $0.06 | $0.84 |
| Ideogram High | $0.22 | $3.08 |

Qwen은 $0.03/MP에서 1024²/1,000,000을 곱한 계산이며 실제 청구의 반올림/최소 단위는 별도 확인한다. Ideogram fal 표시는 이미지 크기와 무관한 장당 가격이다. 표에는 WF-2/WF-3, 구조화 LLM, 재시도·리롤·저장/전송 비용이 포함되지 않는다. Ideogram direct API 가격과 fal 가격을 혼용하지 않는다.

출처, 2026-10-06 관측: [Qwen fal 가격](https://fal.ai/models/fal-ai/qwen-image-edit-2511), [Ideogram fal 가격](https://fal.ai/models/ideogram/v4.5/edit), [fal 입력 계약](https://fal.ai/models/ideogram/v4.5/edit/api), [Ideogram Precise Edit 계약](https://developer.ideogram.ai/api-reference/images/precise-edit/ideogram-4-5).

### 3.2 판단과 비교 방법

Ideogram은 이번 문제의 핵심인 **변경 영역 밖 보존**을 직접 겨냥하므로 비교 가치가 높다. 다만 공식 샘플/제조사 주장이 Lucid의 애니메이션 일러스트 표정 품질 우위를 입증하지는 않는다. 수정 영역 안의 얼굴 형태 보존도 자동 보장은 아니다.

초기 비교안은 같은 neutral 3명(외형 다양성/남성 포함) × 문제가 잘 드러나는 감정 4종, 총 12조건이다.

| 비교군 | 편집 | 후처리 비교 목적 |
|---|---|---|
| A | Qwen + 현행 연출 | 현행 기준, 실제 실패 입력 포함 |
| B | Qwen + 짧은 표정/자세 고정 | 프롬프트·동작 영향 분리 |
| C | Ideogram precision high + Low, B와 같은 편집 의미 | 보존 능력·저비용 후보 |
| D | Ideogram precision high + Medium, B와 같은 편집 의미 | 품질 상향의 비용 대비 효과 |

먼저 편집 직후 결과를 비교하고 대표 실패/성공을 WF-2 단독 및 FaceDetailer 포함 조건으로 보내 후처리 원인을 분리한다. 후보가 살아남으면 필요시 얼굴 내부 마스크 조건, 다른 neutral, 나머지 14종, 반복 seed로 넓힌다. 마스크는 얼굴 외곽/머리카락을 제외하되 눈썹·입을 잘라 표정을 제한하지 않도록 한다.

첫 48편집의 모델 비용만 약 $1.84(1024² Qwen 가정), High 3장 추가 시 $0.66 추가다. **실행 예산 승인이나 실제 실행 기록이 아니다.** GPU·LLM·재시도 별도.

판정은 모델명을 가린 사람이 동일인성/얼굴 길이/눈·입 오류/감정 식별/과한 동작/화풍/스프라이트 교체 시 위치 흔들림/누끼 경계를 보며, **수용 가능한 14종 세트 완성까지의 비용과 시간**을 비교한다. 인물 사진용 얼굴 임베딩 점수만으로 애니 캐릭터 동일성을 확정하지 않는다. 단발 예쁜 결과 하나로 전환하지 않는다.

초기 교체 범위는 감정 편집만 권장한다. 현재 좋은 neutral 생성은 별도 검증 없이는 함께 교체할 이유가 약하다. 기존 `PoseEditClient`는 재사용 가능한 경계지만 표정용 전략·마스크/quality/precision 계약은 추가 설계가 필요하다.

## 4. TTS: 모델과 비용

### 4.1 후보

- `eleven_v4`: 사전 제작 firstGreeting·고정 보이스 샘플에 우선 적합. 사용자의 품질 PoC 성공은 사용자 제공 관찰이며 이번 세션의 실측은 아니다.
- `eleven_v4_turbo`: 동적 대사의 기본 후보. 같은 10개 voice ID와 동일 한국어 대사로 v4 대비 발음·목소리 정체성·연기·과장/태그 낭독·짧은 대사·연속 씬의 억양을 비교한 뒤 결정한다.
- 공식 Turbo 수치는 약 100ms **모델 추론** 중앙값이다. 서버/SSE/텍스트 완성/네트워크/브라우저 버퍼·자동재생 허용을 포함한 앱 첫 음성 지연과 다르다.
- v4와 Turbo를 단순히 같은 과거 TTS HTTP 경로에 모델명만 교체하는 것으로 가정하지 않는다. 모델 문서는 v4 Text-to-Dialogue, Turbo Text-to-Dialogue WebSocket을 안내한다. 마케팅 예제와 reference 차이가 있으므로 실제 계정의 지원 endpoint/model을 소량 PoC로 확인한다.
- 특히 **Turbo WebSocket 연결당 voice 1개, v4는 최대 10개**다. 스토리 다중화자는 Turbo 세션 분리·연결 관리·클립 순서/취소가 필요하다. 다른 사용자/방의 음성이 섞이지 않도록 컨텍스트를 고정한다.

원본 전체 68응답 12,816자와 변형/모드별 분해합 일치, 정상 P1 8,084자와 위 모드별 합 일치, scenes 없는 응답 0을 확인했다. 이것은 소량의 과거 시험 fixture 분포다. 운영 사용자/전체 캐릭터/Boost/장기 대화/극장·시크릿의 분포나 TTS 성공률/실청구/지연을 대표하지 않는다. STORY 대사에 NPC가 포함될 수 있어 공식 10종의 실제 eligible 발화량과도 구별한다.

## 5. TTS UI/UX 제안

### 5.1 첫인사

- 공식 10종의 **고정 firstGreeting**은 v4로 여러 후보를 제작·청음 선정하여 저장, 재생은 무료로 제공한다. 캐릭터 프로필에서 무료 보이스 미리듣기로도 활용할 수 있다.
- 자유 모드의 `ChatService.initializeChatRoom`은 현재 고정 firstGreeting을 로그로 저장한다. 이 경로에는 공통 음성 연결이 자연스럽다.
- **스토리 V2 첫 장면은 고정 firstGreeting이 아니다.** 시작 장소/화자/세계 상태로 무료 OPENING을 동적으로 생성한다. 사전 녹음을 해당 대사에 억지로 재생하지 않는다. 스토리 오프닝의 음성 무료 체험/일반 과금 여부는 별도 미결이며, 무료 생성 남용 경계를 검토한다.
- 첫인사 문구 hash + voice revision에 음성을 묶어 문구 수정 후 옛 음성이 재생되지 않도록 한다. firstGreeting에 가변 호칭이 들어가면 그대로 공통 재사용할 수 있는지 확인한다.
- 새 방의 첫 재생은 사용자의 명시적인 ‘목소리 듣기’ 동작과 연결한다. 보이스 샘플 재생이 유료 자동 모드를 켜는 의미가 되어서는 안 된다.

### 5.2 자동/수동 가격 단위

- 하나의 AI 응답이 여러 씬을 갖는 현행 구조에서, 자동 모드의 비용 단위는 **씬별 추가차감보다 응답 1회**가 설명하기 쉽다. Boost 비용과 별도로 더한다: `(현행 chat/Boost 비용) + 음성 비용`.
- 수동 현재 씬 1E와 자동 응답 전체 1E를 병행하면 같은 콘텐츠에 서로 다른 가격·중복 차감이 발생한다. 초기 대안은 **같은 응답의 보이스를 최초 1회 해금, 수동은 원하는 씬을 재생, 같은 응답의 다른 씬/재생은 추가 차감 없음**이다.
- 표시 예: ‘이 응답 보이스 1E’, 준비 후 ‘다시 듣기’; 자동 모드에는 ‘응답마다 +1E’를 노출한다. 가격은 제안이며 최종 확정이 아니다.
- 해당 응답에 공식 보이스가 있는 캐릭터의 대사가 전혀 없으면 음성 비용을 청구하지 않는다. NPC/내레이션/속마음은 초기 범위에서 제외하고, 임의로 주요 캐릭터 목소리를 배정하지 않는다.

### 5.3 재생 경험

- Boost 근처 ‘보이스’ 토글 + 현재 대사/히스토리의 듣기 버튼을 제안한다. 신규 방 기본 off와 방별 선택을 시작점으로 검토한다. 비용 상태와 단순 mute를 구별한다.
- 자동 모드는 **현재 화면에 도달한 대사**를 자동 재생한다. 음성 완료 후 자동으로 다음 씬으로 넘어갈지는 별도 ‘자동 넘김’ 선호다. 보이스 모드를 켰다는 이유로 사용자의 읽기 속도를 강제하지 않는다.
- 현행 클릭 규칙(첫 클릭 글자 즉시 표시, 다음 클릭 씬 이동)은 유지하면서 실제 씬 이동/새 메시지/리플레이 이동/방 이탈 시 이전 음성을 중단한다. 늦게 도착한 이전 씬 음성도 재생하지 않는다.
- 텍스트는 기존 속도로 표시한다. 음성 준비 실패나 지연이 텍스트 채팅을 막지 않는다. 자동재생 차단은 생성 실패와 다른 상태로 안내하며 준비된 음성을 명시 클릭으로 재생한다.
- 보이스 볼륨과 BGM 볼륨을 구분하고 발화 동안 BGM을 낮춰 대사 명료도를 확보한다. mute/탭 비활성 상태의 자동 생성 여부는 사용자 기대와 비용에 맞춰 명시한다.
- 준비/재생/실패/재시도/재생 무료 상태, 터치 타깃, 키보드·스크린리더 접근성을 목업에서 확인한다.

### 5.4 연기 제어

음성은 `emotion`의 완화된 매핑에서 시작하고 대사·짧은 문맥으로 연기를 보조한다. 감정 하나를 곧바로 고함/울음/과한 숨소리로 고정하지 않는다. 오디오 지시는 우선 0~1개로 비교한다. 14종 이미지 감정은 음성의 에너지·전달 방식과 완전히 같은 축이 아니다. 캐릭터별 보이스 설정을 보존하고 태그 낭독/불필요한 소리/한국어 이름·호칭·숫자·기호를 검증한다.

근거: [v4 voice acting](https://elevenlabs.io/docs/overview/capabilities/text-to-speech/eleven-v4). 실제 10종 voice ID의 한국어 음색/모델 간 일관성은 미확인.

## 6. 구현 전 정해야 할 서버 경계

- 기존 `Character.ttsVoiceId`, `ChatLogDocument.audioUrl`은 준비된 필드이지만 생성/상태/씬별 클립/유효 권리/과금 구현은 아니다. V2 FE `ttsEnabled:false`도 실제 연결을 의미하지 않는다.
- `cleanContent`는 현재 나레이션·화자·대사가 섞인 fallback 표시 문자열이다. **서버가 저장한 씬별 dialogue를 발화 정본으로 사용한다.** V1 speaker null의 기본 캐릭터 규칙과 V2 system/NPC/공식 화자를 구별한다.
- 요청은 사용자 소유 방 + assistantLogId + 안정된 scene index/revision을 대상으로 한다. FE 임의 텍스트/voice ID를 그대로 유료 생성하지 않는다. 스트리밍 중 임시 씬과 최종 저장된 씬의 대응 계약이 필요하다.
- 중복 클릭/자동·수동 겹침/재연/다중 탭은 같은 응답 manifest 및 생성 task에 합류한다. 음성 캐시 키만으로 결제 여부를 대신하지 않는다. 공식 firstGreeting 공개 캐시와 개인 대화 오디오의 권한/서명 URL/삭제·보존 정책을 구별한다.
- 응답 해금 시 대상 씬·text/voice/model/settings revision을 고정한다. 저장 음성이 사라졌다는 이유로 동일 해금 권리를 다시 판매하지 않는다. 보존 기간과 재생 가능 기간은 명시해야 한다.
- 텍스트 채팅 차감/환불과 음성 추가분 차감/환불은 별도 거래 식별자와 free/paid/charged 분할로 추적한다. 음성 실패가 성공한 채팅 응답을 롤백하거나 텍스트 비용을 환불하지 않게 한다.
- 초기 단순 정산 후보는 ‘해당 응답의 대상 클립 일괄 준비 후 음성 1E 확정, 준비 실패 시 음성분 환불’이다. 먼저 재생 가능한 클립을 스트림으로 들려주면서 후속이 실패하는 경우, 또는 지연생성/부분 성공을 허용하는 경우는 환불/재시도 책임을 따로 정해야 한다. 일괄 준비가 첫 음성 지연을 악화하는지 PoC로 비교한다.
- 공급자 타임아웃은 미청구·실패 확정과 같지 않다. 결과를 확인할 수 없는 요청을 무조건 재전송하지 않고 외부 요청 상태/비용을 추적하며 공급자 재시도 횟수를 제한한다.
- 전송 데이터는 발화 대사와 꼭 필요한 짧은 문맥으로 제한한다. 기존 채팅 전체/속마음/불필요한 프로필을 보내지 않는다. 계정의 training opt-out은 전송 전에 확인한다. `enable_logging:false`를 모든 계정에서 가능한 것으로 가정하지 않는다: 공식 TTD 문서는 Zero Retention을 Enterprise만 지원한다고 명시한다.

출처: [Privacy training opt-out](https://elevenlabs.io/privacy-policy), [TTD retention 계약](https://elevenlabs.io/docs/api-reference/text-to-dialogue/convert); 로컬 `ChatStreamService.buildRichCleanContent/buildScenesJson`, `ChatStreamServiceV2.buildScenesJson`, `User/EnergySplit`, FE `ChatPage.jsx`의 `parentLogId`·리플레이 및 `AudioEngine.jsx`.

별도 컨텍스트 독립 검토는 응답당 해금 후보가 자동/수동 분모 차이를 줄인다는 점, 캐시와 지속되는 권리의 분리, 대상 revision 고정, 전체 준비/부분 성공의 정산 차이, 무료 E로 인한 수익 추정 한계를 확인했다. 이는 사전 설계 검토이며 구현 안전성 검증 통과가 아니다.

## 7. 권장 진행 순서와 미결

1. 이미지 중간 결과 비교로 프롬프트/Qwen/WF-2/FaceDetailer 영향 분리, Ideogram precision high Low/Medium 비교.
2. 공식 10보이스의 한국어 동일 대사 v4/Turbo 비교, 실제 앱 경로의 첫 음성·전체 생성 지연/청구량 확인. 대표 평상·수줍음·불만·슬픔·짧은 대사·긴 대사 포함.
3. 응답당 비용/길이 상한·실패 정산·고정/동적 첫인사·초기 모드 범위를 구체화한다. 자유부터 도입 후 스토리 다중화자·극장/UGC·시크릿 적용은 각 범위로 판단한다.
4. 공식 첫인사/자동 토글/수동 듣기/재생 상태를 **검토 가능한 목업**으로 만들고 사용자 디자인 승인 후 구현한다.
5. 구현 시 중복 생성/권한/잘못된 화자·수위/실패 환불/늦은 오디오/재연/캐시·삭제를 정상 입력과 실제 실패 입력으로 검증한다. 유료 품질 실험의 요청·비용·결과를 원장에 보존한다.

미결: 계정 실제 요금제/endpoint 접근/voice revision, 공급자 청구 문자열 계산, 운영 대사 길이·동시사용·무료 E 분포, Turbo의 해당 목소리 연기 품질, 동적 오프닝 음성 가격, 초기 스토리·극장·UGC·시크릿 범위, 음성 보존 기간과 과금/중단/부분 실패 계약.

## 8. 2026-10-06 사용자 합의·실험 후속

이전의 비교 제안은 사용자 지시로 실제 실행했다. 연의 동일 neutral에서 Qwen 현행/짧은 표정·자세 고정 및 Ideogram Precise Edit Low/Medium을 5감정씩, 편집20 + WF-2/FaceDetailer20 실행했다. 결과와 비용·원장·운영 복원은 [실험 정본 docs/30](30_Studio_Emotion_Bakeoff_2026-10-06.md)을 우선한다. Ideogram raw 무변경3건과 후처리 재생성을 확인했으며 일괄 모델 교체는 아직 하지 않았다.

사용자는 적당한 몸동작을 유지하고, 캐릭터별 동적 감정 repertoire를 생성·영속화·시스템 프롬프트에 반영하기를 요청했다. 자세 고정은 실험용이다. 진행 순서는 스튜디오 다음 TTS다.

TTS 자동 모드는 LLM이 표시용 대사와 별도로 연기 태그가 있는 TTS 입력 필드를 출력하며, 수동 요청은 별도 입력 변환으로 구현한다. 모델은 환경변수로 관리하고 v4/Turbo 품질 비교는 구현 후 사용자가 직접 한다. 앞 절의 '서버가 dialogue에서 직접 렌더' 제안은 이 사용자 요구에 맞춰 조정한다. 별도 필드도 저장된 대사/화자/revision 및 서버 voice 권한과 연결하며 임의의 내용이나 공급자 파라미터를 그대로 통과시키지 않는다. 가격·실패 정산·오프닝 범위는 구체화가 남아 있다.
