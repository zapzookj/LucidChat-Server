## G. 검증 규율 (이 세션에 적용)

1. **구조적 편집은 Edit 도구.** CRLF다. 다중행 `sed`/`node` 치환 금지.
2. **완료는 grep으로 판정.** 도구 반환값이 아니라 최종 파일 상태.
3. **컴파일 통과 ≠ 완료.** 가드·게이트·플래그는 문자열 grep으로 개수를 센다.
4. **새 빈·파생 쿼리를 넣었으면 `bootRun`.** `Started AichatApplication in` 확인.
5. **FE는 `vite build` 아니라 dev 서버 모듈 평가.** `await import()`로 실제 평가.
6. **새 거부면(400/409)은 `GlobalExceptionHandler` 매핑 + FE 복구 경로를 같은 커밋에.**
7. **픽스 커밋마다 `21_assets/scope_ledger.md`와 델타 행을 같은 커밋에서 갱신.**
8. **배치마다 새 컨텍스트의 적대적 검토.** 이번 준비에서도 검증층이 판정 2건을 뒤집었다.

## J. 이 준비의 한계

- 재판정은 **에이전트 판정 + 적대적 검증 + 표본 grep 8건**이다. 내가 직접 코드로 대조한 것은 8건이고,
  나머지는 각 항목의 `evidence` 인용이 근거다. **착수 직전 해당 심볼 grep은 여전히 권장한다.**
- 프로드 실측 0건 — §H가 전부 미집행이다. 그래서 `D-5.6`·`B-5.2`·`D-18`·`9-A′` 판정에 불확실성이 남는다.
- 설정 감사에서 **미확인 2건**을 남겼다: `BgmMode.DAILY_CALM`의 CHECK 동기(로컬 postgres 컨테이너 전부 Exited·psql 미설치)
  와 `AuthProvider.KAKAO`(개통일 드리프트 가능).
- 스윕3이 별건으로 지적: **마이그레이션 체인이 빈 DB에서 재생 불가**하다(V2가 무가드 `ALTER TABLE users`, 같은 유형 16파일).
  재해복구·스테이징 신설 축이 검증된 적이 없다. 런칭 전 별도 안건으로 세울 것을 권한다.
