## 승인과 범위

## 구현

- `ConceptStructuringService`의 원화 태그 요청은 실제 A 요청의 시스템 지시를 그대로 사용한다. appearance/persona/scene 세 배열을 생성하며 개수·서버 스타일 태그를 강제하지 않는다. 선택 성별은 컨셉 데이터 한 줄로 전달하고 종전 긴 남성 태그 브리프를 제거했다.
- 프로필은 별도 요청으로 생성하고 확정된 세 배열을 참조한다. 메타데이터 요청이 반환한 이미지 태그는 무시한다. 이름·프로필·무드·누끼용 배경색·기본 자세·검수는 기존 메타데이터 계약을 유지한다. 초기 나이·검수·외형·복장 필수값과 태그 배열/항목을 검증한다.
- WF1 positive는 세 배열의 순서와 중복을 보존해 조인한다. quality/style/gender prefix, 스타일 필터, 중복 제거를 적용하지 않는다. WF1 negative는 성별과 관계없이 빈 값이다. WAI·detail LoRA·해상도·샘플러·FaceDetailer·기본 배치2는 유지한다. 남성 LoRA는 선택 성별에 따라 유지한다.
- 원화 리롤도 같은 이미지 지시를 사용한다. 기존 디자인/부분 변경 요청/전체 리롤 지시를 컨셉 데이터로 전달하고 외형 메타데이터를 후속 생성한다. 리롤 검수의 2차 판단에 이번 디자인 요청을 함께 전달한다. 최신 프로필의 사용자 편집·서사·첫인사는 보존하고 이미지 세 배열을 병합한다. 과거 배치 선택 시에도 세 배열을 스냅샷에서 복원한다. legacy null persona는 기존값을 유지한다.
- 같은 실행 안에서 성공한 이미지 태그를 메타데이터 재시도에 재사용한다. 성공한 전체 산출도 DB 반영 재시도에 재사용한다. 새 LLM 단계/재시도 전에 현재 상태를 확인해 취소된 작업의 후속 유료 요청을 중단한다. 이미 실행 중인 외부 요청을 취소하는 기능은 아니다.
- 원화 실행 동시 진입을 프로세스 내에서 억제하고, accepted GOLDEN receipt는 폴러가 처리하도록 재진입 시 새 요청을 보내지 않는다. GPU POST 직전 DB락으로 `K_GOLDEN_SUBMITTING`을 저장하고 성공 시 receipt와 배치 스냅샷을 한 트랜잭션에 기록한다. 불명확 POST/재시작 후 receipt 없는 예약은 자동 재POST하지 않고 기존 free/paid 분할대로 실패 환불한다. 정상 완료 후 사용자 발의 리롤은 새 배치를 제출한다.

중립 스탠딩(Qwen+WF2)·동적 감정(Sunburst Low/사용자 리롤 High)·누끼·TTS·FE·에너지 단가는 변경하지 않는다. 정상 Stage0/디자인 리롤은 이미지+메타데이터 두 논리 요청이다. 같은 모델/temperature0.7/max_tokens8192를 사용한다. OpenRouter 클라이언트의 기존 length 응답 예산 확장과 실패 재시도 때문에 실제 HTTP 횟수가 항상2라는 뜻은 아니다. 이미지 태그 캐시는 해당 비동기 실행 수명에 한정되며 프로세스 재시작을 넘는 영속 캐시가 아니다.

예약 복구와 실행 진입 set은 현재 단일 `lucid-app`/JVM 전제다. 여러 앱 인스턴스가 동시에 살아 있는 구성으로 확장하면 다른 인스턴스의 활성 예약을 유실로 오판하지 않도록 lease/소유권 비교를 추가해야 한다. 분산 LLM 실행 중복 방지까지 검증한 것으로 표현하지 않는다.
